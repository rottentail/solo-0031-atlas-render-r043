# 交换包导入验证与故障注入

本目录的自动化验证覆盖 `POST /v1/imports/{id}` 的事务原子性与对抗输入。基线项目没有测试套件，本验证作为独立质量保障层加入，不改变任何生产校验逻辑。

## 运行方式

```sh
make verify-import          # 带竞态检测的完整验证
go test ./...               # 全部 Go 测试
go test -race -count=N ./internal/bundle ./internal/persist ./internal/service ./internal/httpapi
```

测试不监听网络端口、不需要预置环境；每个用例在独立临时目录中打开带文件锁的存储，结束自动清理。HTTP 用例通过 `httptest` 在进程内挂载真实路由。

## 故障注入机制

### 1. 测试专用写函数注入

`internal/persist/export_test.go` 仅在测试二进制中编译（`_test.go` 后缀使生产构建完全看不到该文件）。它通过 `Store` 已有的可替换写盘函数字段注入错误：候选状态先经过与正常提交完全相同的 `persist.Validate` 生产校验，随后在临时文件写入阶段返回模拟的磁盘 I/O 错误，内存状态不发生切换。

### 2. 只读目录的真实文件系统故障

`internal/persist/import_fs_fault_test.go` 不依赖任何测试钩子：把状态目录权限改为只读，让生产原子写在 `CreateTemp` 阶段真实失败（root 用户会绕过权限位，该用例自动跳过）。这从操作系统层面独立验证了失败路径。

关键边界：

- 注入点位于校验**之后**，因此不会、也无法绕过任何生产校验；另有专门用例验证故障期间非法包仍在验证阶段被拒，且写盘函数零调用。
- 生产代码（含 `Store` 的字段与原子写实现）未为测试新增任何可从非测试包访问的入口。
- 原子写实现（临时文件 + fsync + rename）保持原样；测试额外断言失败后目录中不存在 `.atlas-write-*` 残留。

## 原子性依据

`service.Import` 的所有状态修改都在单次 `Store.Update` 事务闭包内完成：闭包先在状态克隆上收集全部冲突并返回错误，任何冲突都阻止提交；提交前再跑一次完整 `persist.Validate`，随后才原子落盘并切换内存状态。因此“拒绝后不留下部分素材或场景”由事务结构保证，测试从内存、磁盘文件、目录残留、事件序列四个可观察面分别核验。
